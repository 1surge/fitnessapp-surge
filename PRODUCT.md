# Surge Fitness
<!-- impeccable:product-schema 1 -->

## Platform
web

## Stack
Existing vanilla HTML/CSS/JavaScript with data.js; no framework migration or runtime dependencies. On-device storage by default with an optional user-chosen folder (Drive/OneDrive/iCloud via the File System Access API where the browser allows it, export/import everywhere else). No SURGE-run accounts, no SURGE-run cloud.

## Audience and scene
Public training log for anyone who trains, primarily used on a phone in a noisy, crowded gym. No age framing, no identity collection. Oliver reviews on his OPC14 laptop; Hermes runs on SMC1. Never hand over localhost as a laptop URL. Current project is S:/Oliver General @smc/FitnessApp/.

## Jobs and content
A new user should understand the product and start a useful session without entering a name, personal reason, body details or other personalization. Know today's plan; learn unfamiliar exercises with real videos; log weight, reps and completed sets quickly; pause, resume, skip, substitute, cancel, review history, export a backup. Five weekday visits: three full-body strength sessions and two easier recovery sessions. Existing populated exercise, stretch and education data must survive. Personal preferences may be optional later, but the core product must work anonymously and generically.

## Safety and psychology
Technique, gradual progression, and a coach's eyes on new lifts before load. No maximal-lift encouragement, guilt, body comparison, calorie targets or restrictive eating. Reduce choice overload and make the next action clear. Recovery counts as intentional training. User asked for psychology-driven design, not unsupported behavior-science claims.

## Brand commitments
User likes Surge Fitness and provided plate-badge logos as creative starting points, not a mandate to reproduce them. Full visual discretion delegated by user. Existing generic dashboard and subsequent red/neon reskins explicitly rejected; replace visual structure as well as styling. Mobile usability, accessibility and truthful functionality win over effects.

## Constraints
Entirely free services if any; no purchase or cloud provisioning in this redesign. Preserve current reviewed index.html and create surge-v2.html beside it. Do not fabricate metrics or integration status. Use real browser screenshots of screens and interactive states before presenting.
